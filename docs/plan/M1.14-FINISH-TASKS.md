## Operating rules

One mutation-capable worker at a time in this worktree. Each task gets a
focused acceptance gate, a durable commit when it changes files, and a report
of the exact head, commands/results, artifacts, and remaining gaps. Changes
necessary to repair a failing test within the assigned feature are authorized;
unexpected product/security decisions return to the parent. No nested agents,
pushes, PRs, merges, or production changes by workers.

Use focused tests while implementing. The full Go suite ordinarily takes
7–8 minutes; run it once per relevant integrated gate rather than repeatedly
inside every small task. Browser runs are serialized. Install locked web
dependencies, use the Node major from `.nvmrc`, build the SPA, and supply the
documented dev DATABASE_URL before focused Playwright commands. Never use
an implicitly downloaded unpinned test runner. UI proof uses verify-fold and
verify-ui with retained images and manual inspection at 390px.

Workers receive a 60-minute maximum with a five-minute checkpoint warning;
the task boundaries, rather than repeated full suites, keep normal work much
shorter. A partial handoff is resumable and is not acceptance. No passing
test, completed worker, or checklist alone grants publication approval.
