# M1.8 / M1.9 judgment calls (Wright)

Running log of calls made without escalating: what was chosen and why. The original lived at
/workspace/fold-ui-audit/M1.9-JUDGMENT-CALLS.md and was lost in the Oct 21, 2026 box wipe (about 9:39 PM MT). This copy was
rebuilt from STATUS.md, the PR bodies of #105/#106 and Wright's notes; wording of early entries is
reconstructed, and the numbering is new. It lives in the repo from now on.

1. **Order: finish M1.8 before M1.9.** M1.9 slice 2 (registering household people) counts seats and waitlist
   through the pool logic M1.8 slice 2 adds, so remote capacity went first, then the M1.9 slice 1 backend, which does not depend on it.
2. **One waitlist per date, split by mode.** Remote and in-person share one line ordered by `waitlisted_at`; each
   pool promotes only entries of its own mode, and a too-big party never blocks the other pool.
3. **Remote capacity null = unlimited.** Matches in-person capacity. The event-level limit 0 is refused
   (uncheck remote instead, Illuminator #105 M2); a per-date override of 0 stays allowed to close remote for one date.
4. **Guests attend in person.** Guest registrations default to `in_person`; remote is for signed-in members.
5. **Childcare has no waitlist** (M1.8 slice 3, per the brief): when childcare spots run out, the parent can still come
   without childcare.
6. **Re-enable behaviour unchanged by M1.8:** a re-enabled account dropped from a full date is re-added only by a leader, who may go over capacity (M1.5).
7. **M1.8 video boxes ticked in #105** only for items with tests on master.
8. **M1.9 slice 1 shipped backend-only (#106).** The UI was split off so knip stays green and review stays small;
   household types were taken out of the guard's tsContracts until the UI added them back (this PR).
9. **Migration numbers** follow master at branch time (00020 remote, 00022 households); renumber on conflict, never edit a merged one.
10. **`GET /me/household` is read-only** (Warden, #106): `{household: null}` until created, and for teen accounts;
    creation only via `PUT /me/household` or the first `POST /me/household/people`.
11. **Guardian self-confirm (DEC-79, Grier):** blocked while another *active* admin exists (caller excluded
    explicitly); a sole admin may self-confirm and the audit marks `selfConfirm`. Self-reject is unrestricted.
12. **Warden follow-ups from #106:** slice 2 must check a `kind: adult` person against the birth date; a confirmed teen link surviving a switch to child is left as is.
13. **#105 Whittler fixes:** a waiter switching mode gets a fresh `waitlisted_at`; `PickPromotions` and the
    always-false cutoff param removed; free-seats map instead of a closure. The admin re-add double count is a follow-up in STATUS.md.
14. **"Seats" wording kept in #105** until Illuminator answers about "remote spots".
15. **Codex unavailable after the wipe** (binary and auth gone). The M1.9 slice 1 UI was written by hand rather than
    touching Codex auth.
