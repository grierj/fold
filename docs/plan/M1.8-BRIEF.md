# M1.8 brief: video, remote, childcare

Source of truth: PLAN.md 5.8, 5.3 (event fields), 8.2 (feeds), DEC-16, DEC-38, DEC-47, and the M1.8 acceptance list. M1.8 ships in slices; each is its own PR.

## Slice 1: video links and `video_reveal` (this PR)

- Migration `00019`: on `events`, add `video_provider` (`none|link|jitsi`, default `none`), `video_url` (text, default `''`), `video_reveal` (`always|registered_only`, default `registered_only`), with CHECK constraints. Add the `jitsi_domain` setting read (default `meet.jit.si`).
- Event create and update accept `videoProvider`, `videoUrl`, `videoReveal`. `videoUrl` must be an absolute `https://` URL (max 2048) when the provider is not `none`; `none` clears the URL.
- `POST /api/v1/events/video/jitsi` (leaders, hosts, admins; CSRF) returns `{url}`: `https://<jitsi_domain>/<church-slug>-<12 random chars>` from crypto/rand, no API call. The church slug comes from `church_name` (lowercase, a-z0-9 and hyphens; `fold` if empty). Each call gives a new URL.
- Reveal rule, one policy function `policy.CanSeeVideoLink(reveal, isGoing, isManager)`: `always` shows everyone who can see the event; `registered_only` shows only people registered `going` for that date, plus the event's leaders or hosts and admins. Waitlisted, maybe and declined do not see it (personal feeds widen this for maybe and unanswered members: DEC-70).
- Applied in: the event API (`videoUrl` omitted when hidden; `videoHidden: true` so the UI can say "Register to get the link"), personal ICS feeds (per occurrence, going only, under `registered_only`), and the public feed (only `always`). Emails that carry event details (promotion "you're in") include the link only when the recipient may see it.
- UI: the event form gets a Video section (None / Paste a link / Generate Jitsi link button; reveal select defaulting to "Registered people only"). The event page shows the link as a plain anchor with `target="_blank" rel="noopener noreferrer"`. No iframe or embed anywhere (DEC-16); a test greps web/src for `<iframe`.
- Tests: policy table for `CanSeeVideoLink`; API tests (going sees, waitlisted/outsider don't, leader does, `always` shows all); feed tests (personal and public); Jitsi URL shape and uniqueness; validation of non-https URLs.
