# Event visibility

Each event has its own visibility, copied from its group when it is scheduled. A leader can make one event narrower or wider than the group. When the group becomes more private, events that only inherited its visibility tighten, and the leader must decide whether each event they opened wider stays open or tightens.

## Sub-features

- `event-visibility-narrow` sets one event narrower than its group; people outside the new visibility no longer see it on the group page.
- `event-visibility-open` sets an event wider than its group; the page says a leader opened it.
- `group-tighten-review` making the group more private shows a review dialog; inherited events are listed to match, and the confirm button stays disabled until every leader-opened event has `Keep it …` or `Make it …`.
- `event-visibility-series-reset` changing the series visibility keeps a date's own visibility, or clears it when the leader ticks `Also reset those dates to the series setting`.

## How to get to it (user POV)

- Visibility is chosen when the event is created: the schedule forms have a `Who can see this event` radio group under `More options` that starts at the group's value (church-wide: public). After creation there is no control on the event list; it lives inside `Edit series` (or `Edit event` for a single event): in the date's `More for <title> on <date>` menu on the group page, and as an `Edit event` button on the event page, with `Save visibility`.
- On `/events/<id>`, the same control appears for a leader.
- On a group page you lead, `More group actions` → `Edit group`, pick a more private option under `Who can see this group`, and `Save group` opens the review dialog.

## Gotchas

- Public to private with an inherited event also opens the dialog (that event will match the group). Wait for the dialog with `waitFor()`; a `count()` check races it.
- An event set equal to its group's visibility is not leader-opened, so tightening the group tightens it with no question.
- Registrants who would lose access are counted in the dialog (`N person registered will be cancelled and notified`); they get a `Registration cancelled: <title>` notice that names neither the group nor its place.
- Narrowing `Wednesday class` leaves it invite-only. A later recipe that needs a public event date (guest registration) must use another event.
- On the group page, right after `Save this date` the first `Edit this date` click did not reopen the form in a driven run; the second click did (observed, cause not investigated). Retry the menu choice and wait for `Save this date` before picking a radio. Reloading the page also works.
